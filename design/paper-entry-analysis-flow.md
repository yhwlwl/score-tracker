# 试题录入、题型统计与 AI 分析链路

本分支从最新 main 整合 PR #40、#43、#46，并处理统计页入口、打包顺序及当前 main 的冲突。新的 PR 直接以 main 为 base；不需要先合并那三个旧 PR。旧 PR 不自动关闭。

## 用户流程

底部「分析」提供四个并列入口：成绩分析、试题录入、题型分析、AI 试卷分析。

1. 「试题录入」选择科目及可选关联考试，上传原卷、答题卡和参考答案（合计最多 15 张）。保存草稿或开始识别。该页只提供录入需要的选项，不混入讲解、练习、复习安排等分析设置。
2. 识别后得到独立保存的试题记录。展开题目，核对题干、原作答、教师批改得分和满分，补充稳定的题型名称、可选难度，再保存核对。原始错误写法保留；AI 估分与教师得分分开。
3. 「预览并同步题型得分」按题型合计已核对的教师分。未分类题不纳入；未核对的分类题必须先核对。某个题型中任何一道题的得分或满分未知，合计相应字段保持 null，保存为待补全，不把其他已知题冒充完整题型。明确 0 分保留。同一题型难度不一致或未标齐时，不给合计强加统一难度。
4. 确认预览后，仅更新已关联考试本科目的 `question_type_scores`。其他科目及整科、总分、赋分、原始分不改动。已有本科题型时展示现有数据，并要求勾选明确的替换确认。重复同步替换同一份本科记录，不把整组总分与小题重复相加。随后可直接进入 PR46 的历史题型分析。
5. 「生成 AI 分析」只提供分析设置。后端使用已保存的题目和核对记录建立独立快照，从逐题诊断开始；不再从目录、作答匹配或分数识别阶段重跑。可选择结合原图理解图形，也可仅使用文字；原图直接从账号私有存储复用，无需客户端重新上传。

AI 识别录入与新建 AI 分析各使用一次既有试用次数；同一请求重试不重复计次。题型同步、查看和手动核对不调用模型。这里沿用原有计次机制，没有新额度表。

## 数据边界

- 录入和分析继续使用现有 `score_tracker_paper_reviews`，通过 `options.purpose` 区分入口。分析结果携带 `source_record: {request_id, revision}`，保存源记录的题目/作答快照。后续修改原录入不会悄悄改写已完成分析。
- `correct` 向后兼容增加 `question_type`、`question_difficulty`。旧客户端不发送这两个字段时保留现有值。OCR 读取原卷题型栏目，并允许手动修正。
- 新增动作 `analyze_record`、`preview_types`、`sync_types`。所有动作先验证现有会话，按账号取源记录和目标考试。分析预留额度沿用数据库原子 RPC；源修订不一致时不开始新任务。
- 同步以考试 `updated_at` 作为预览版本；最终写入还带条件更新，冲突时要求重新预览。只写一个科目，保留其他科目。对原始满分/原始分的校验与 PR43 共用同一模型。
- 从新建考试进入录入时沿用原草稿编号。保存考试后的 `attach` 同时关联已识别记录和未提交扫描件草稿，避免草稿在开始识别后丢失考试关联。
- 关联分析只读复用源扫描件；删除分析不删除原录入和原扫描件。删除原录入会删除其扫描件，已有分析的文字快照、已同步题型分继续保留。继续分析遇到源扫描件已移除时，使用已有文字快照。
- 不新增数据库结构。仓库带入的迁移来自上述旧 PR，生产所需字段已通过只读结构查询确认存在。
