# 数学大题超时恢复

19 题报告在完成 16 题后，末尾三道大题被反复整批重试。诊断记录显示请求实际因模型等待超时终止；运行时又因实例剩余时间不足，将错误改成 `worker_deadline`。这使流程进入原样换实例续接，而没有触发拆小批次。旧报告的自动续接和手动恢复额度因此耗尽。

修复包含：

- 未明确满分的大题，也可凭两小问或已确认的较大教师得分识别为复杂题，单独使用原有推理预算。教师得分只用于任务分批，不补写满分、不推定满分或正确性。
- 模型请求已经发出后，保留 `upstream_timeout`、`invalid_model_output` 等真实错误；实例剩余时间不足只记录为 `deadline_limited` 并停止在本实例内重试。只有调用前预算不足且尚未发请求，才返回 `worker_deadline`。
- 多题失败后进入单题恢复，清除不能复用于单题的整批 JSON 修复文本；保留此前已完成诊断。
- 手动恢复重新获得有上限的实例续接预算；旧版误归类的模型失败在恢复时主动拆成单题。原恢复次数限制、用户归属校验、请求指纹、开始计次和满分题分流均保留。

`design/test-paper-review-deadlines.cjs` 使用实际运行时、处理器和隔离数据库模拟，验证接近实例时限时保留错误、无效 JSON 原文可诊断、16/19 断点保留、整批超时后变为 17/18/19 单题、旧记录恢复、满分题批次效率，以及整个过程没有新增分析预约。

上线后可对已确认受此问题影响的指定报告做一次维护恢复：保留题目、作答、扫描件、前 16 题诊断和诊断历史，仅恢复为可继续状态、指定单题批次，并补回被该缺陷耗尽的恢复机会。恢复计算仍通过用户登录后的正常“继续分析”入口发起，不增加公开维护接口或绕过用户鉴权。
