# 科目内 AI 试卷分析

入口：添加 / 编辑考试 → 每个科目底部「AI 试卷分析」。普通打开表单、录入成绩和保存考试不会调用此功能。

## 报告与分析约束

报告依次展示考试背景与核心结论、已经做到的步骤、分组表现与可核对的失分分布、跨题观察、复习行动和验收标准，最后展开逐题详情。逐题详情保留原题、作答转录、来源页、批改依据、正确前缀、第一处可证实的问题、下一步、迁移方法和小练习。练习答案另行展开，避免直接泄露在验收标准里。

分析适用于不同用户、年级和学科。提示词按学科使用条件与方程、材料与论证、语言与任务要求等方法，没有内置真实评测试卷的题号、答案或学生分数。成绩截图仅作为本次考试的背景，不以裸分猜相对水平，不插值百分位，不承诺提分。

- 以原卷一级题号为计分单位，大题的小问保存在 `subparts`；不把教师大题总分拆分、平均分配到小问。
- 教师分数须有对应题号、来源页和可读批改数字；未识别、未批改、未完成不自动等于0。满分来自印刷说明；只有明确每空/题分值与可计数的单位时才允许计算，并校验算术。
- 计算逐题合计、满分合计、可核对分组与整卷分数。冲突时重读一次，仍有冲突则标明待核对，不采用矛盾的逐题得分与比例。合计相符只证明算术相符，不能证明批改位置和选项归属正确。
- 有作答时另发一次独立读取请求，只给题目身份和原图，不传上轮学生选项、批改分或AI解答。两次读取不能相互确认的逐题分数或填涂保留未知，再据更新后的事实分析。清晰的分组总分可保留，不分摊到各题。
- 失分诊断应保留正确前缀，定位具体卡点。第一错步的引文无法与作答转录对应时降级待确认。教师满分与AI判断冲突时不列为补弱优先项；无法读取的选项不进入具体薄弱点排序。
- 跨题归纳需考虑做对题目的反证；单题观察标为待验证。不能从错误或空白倒推粗心、学习态度、考试时间分配等行为或心理过程。
- 无作答时只整理题目与解法，不生成个人优劣或失分归因。无参考答案时明确为AI推导，不能冒充教师评分细则或标准答案。有明确评分细则时可显示独立AI估分并引用依据，不纳入教师分数或人工核对汇总。
- 支持手动核对作答、教师分数、满分，标记已核对 / 已订正。用户核对汇总只包含完整的计分单位，不包含AI估分。人工修改保留原始AI结果，并提示原有评价尚未重新生成。

## 上传与任务执行

支持 JPG / PNG / WebP，共1～8页，每张原图最多10MB。可上传试卷、独立答题卡和参考答案，并注明试卷包含作答。支持预览、前移、旋转和移除。PDF暂须转成图片。

浏览器保留最大3600像素的主图。宽幅资料自动生成六个有重叠的局部，帮助读取多栏细小文字；局部仍属于原页，不增加用户页数，也不作为新题重复统计。所有上传数据合计不超过12MB。用户入口和报告无需展示模型参数。

模型请求与成绩识图隔离，不能复用其 `thinking=disabled`：

1. 事实提取：低强度推理，建立题目、作答和批改底稿。
2. 独立读取：低强度推理，重新确认分数位置和选择题填涂；不锚定第一次结果。
3. 逐题诊断：失分与复杂题使用高强度推理，每批最多4个短题，复杂大题单独处理；满分题用较轻推理核验已有能力。过长批次遇超时或截断自动拆成单题继续。单题仍未得到可靠解答时保留识别和批改信息、明确标记待核验，形成部分报告，不编造答案或失分原因。
4. 最终复核：低强度推理，检查必要修改、归纳有证据的模式，生成互不重复的行动及验收标准。

每次模型调用输出上限24576 tokens（包含供应商计入的推理用量），每个阶段最多等待125秒，恢复尝试共用阶段时限。不同阶段使用不同后台请求，避免整份报告受一个90秒预算限制。推理参数不受支持时明确报错，不静默关闭推理。整卷需要数分钟，复杂题、多次复核或网络恢复可能更久；耗时不作为质量指标。

阶段间保存结构化检查点并转发内存中的图片，使用服务端认证的内部继续请求和一次性认领值，重复投递不会重复调用模型。用户可以返回考试，随后从分析记录查看。后台超过4分钟没有阶段进展才标记中断，不以整份报告创建时间判断超时。

中断记录在仍保有原有图片时可继续，必须校验所有者和相同请求内容，每份报告最多继续两次，不另预留一份报告额度；已完成的阶段和真实失败历史保留。若浏览器已不保有本次图片，需要重新选择同样的资料和页序。后台检查点不含图片，不能凭空恢复丢失的上传内容。

## 隔离、权限与数据保留

功能仅使用新增的 `score_tracker_paper_settings`、`score_tracker_paper_reviews`、`score_tracker_paper_usage` 和 `score_tracker_paper_*` RPC。检查点迁移只给报告表新增 `analysis_state` 和 `progress`，不修改原有成绩、识图或额度数据。

原图与局部图片只在浏览器、处理内存和模型请求中使用，不保存到本站数据库或Storage。保存结构化报告、核对记录和服务端诊断；`analysis_state` 仅保存结构化转录、阶段和认领值，完成后清空。第三方模型按其服务条款处理图片，上传前有明确确认；没有默认训练授权或公开题库。

表启用RLS，撤销PUBLIC / anon / authenticated访问，RPC仅service_role可执行。Edge Function `verify_jwt=false`，用户接口在内部验证项目自定义会话SHA-256摘要、有效期和所有权；内部继续接口仅接受服务端凭据，客户端不能指定所有者或认领值。关联考试验证所有权，核对更新使用revision处理并发。

用户接口显式列出可返回字段；`analysis_state`、原始模型输出、模型配置和私有排障记录均不返回。删除报告同时删除检查点和诊断；删除考试 / 账号时关联报告由外键清除。保存报告、核对或继续任务都不会自动改变考试成绩。

初始独立试用额度仍为每账号每日3次开始请求、全站每日20次、间隔60秒，北京时间0点重置。失败的开始请求仍计次，重复同一请求不再预留次数，删除报告不恢复次数。整卷会使用多次模型调用；业务次数按报告计，实际调用数与用量另记诊断。成绩识图的设置、功能和额度不变。

## 准确的诊断记录

服务端保存 `started_at`、`duration_ms`、`model`、`provider_host`、`upstream_status`、`error_code`、`error_stage`、`error_detail`、`attempts`、`diagnostics`、`raw_output`、`image_count`、`image_bytes` 和 `image_meta`。

`attempts` 记录每次实际调用的阶段、时限、耗时、请求编号（供应商确实提供时）、HTTP状态、脱敏错误、重试原因、截断或解析失败、实际使用的推理设置、输出限制、图像数量与字节、提示词摘要，以及prompt / completion / reasoning tokens。`diagnostics`保留阶段时间线、提示词版本、默认预算与日志落库异常。推理tokens或字符数量不等于独立质量保证。

图片元数据含主图与局部的数量、类型和实际解码字节，不存原图、文件名、会话令牌或API key。`raw_output`仅保存最多100000字符的脱敏回答内容，绝不保存模型内部思考原文。检查点和每次调用顺序落库；只有报告成功保存后才记录完成。历史未知错误保持未知，不补造原因。

## 部署与验证

应用本分支新增迁移，仅部署 `score-tracker-paper-review` 及相对依赖，再使用分支前端预览。内部继续请求复用这个新函数，不重新部署旧识图函数。未合并分支时，现有生产页面没有新入口。可以单独关闭新配置的enabled，已有报告仍可读取。

```
node design/build-bundles.js
node design/bundle-check.js
node design/test-paper-review.cjs
node design/test-paper-review-diagnostics.cjs
node design/test-exam-averages.cjs
node design/test-same-origin-api.cjs
node design/test-vision-reliability.cjs
```

测试依赖可在仓库外安装jsdom和@electric-sql/pglite，并通过NODE_PATH提供。测试执行实际handler、编排、错误恢复、归属校验和前端表单，模型响应使用隔离夹具；这些测试不能证明真实手写和学科推理准确。另用用户授权的原始图片和独立英语合成样例作真实调用评测，不把评测答案注入提示词，不将真实学生原图或完整作答提交到仓库。

本环境Chromium运行时SIGTRAP，真实浏览器视觉验收未完成；不能把浏览器测试脚本的存在视为通过。接口、PGlite、jsdom与真实模型复测的结果分别报告。
