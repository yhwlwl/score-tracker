# 版本同步与历史更新

版本号由管理员发布配置决定；HTML中的固定版本与脚本URL只用于判断网页文件是否最新。首次成功检查时，如果当前脚本与同域无缓存读取的HTML脚本一致，采用发布版本；已打开页面在后续检查发现新版本，仍提示刷新。无法验证脚本一致时，不宣称更新完成。刷新结果埋点等配置和网页检查完成后再判断，避免仅凭静态meta把7.1误报为7.0。

自动弹窗只显示当前最新版本，阻塞期间排队的旧版本会被替换。手动打开使用notice_history，最新在前，可切换历史版本；公开响应只包含公告，不包含用户或阅读记录。登录用户的阅读去重、跨标签页claim和账户切换保护保持有效。未登录页静默同步版本，不自动弹窗。

release_history是原有service_role专用配置表的JSON数组，继承现有RLS与权限。后台保存时在同一条带revision条件的UPDATE里保存配置和历史；冲突保存不改变历史。同一版本只保留最新文案，旧版本保留各自内容。默认标题随版本同步，自定义标题保留。

20261001151551_release_version_history.sql由CLI生成，并按实际应用的数据库迁移版本对齐文件名，已通过Supabase迁移工具应用到现有项目；通知Edge Function已部署，verify_jwt=false沿用现有自定义会话认证。原版本公告已被覆盖的自定义编辑无法恢复，v7.0使用当时随代码发布的原公告；当前v7.1保留现有内容。后续版本由服务器完整保存。

验证：版本7.1配合静态7.0meta的首次同步与刷新完成、旧脚本与失败检查不虚报更新、未登录静默同步、手动历史切换、自动仅最新、旧排队通知替换、同版本去重、账户切换、跨标签页、后台默认标题、真实handler的归档/同版本编辑/授权/revision冲突均有行为检查。同域代理、已完成投票、账号找回、含金量回归及静态构建通过。数据库查询确认7.0/7.1历史及当前版本保留；安全检查仅有原配置表service-only设计对应的RLS无公开策略信息项。运行环境直接请求Edge Function超时，因此没有宣称线上完整请求链路或实机视觉已验收。
