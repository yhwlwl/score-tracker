# 全站字体与阅读层级

`typography.css` 在基础样式和移动端修正之后加载，以同一套字体和字号覆盖公开应用与管理后台。保留原有主题、信息结构和数据口径。

字体优先使用设备的 `system-ui`，再回退到 Segoe UI、苹方、冬青黑体、微软雅黑及 Noto Sans CJK SC。没有新增网络字体请求；中文与拉丁数字随设备选择合适的本地字体。主要字重使用 400、500、600，数值采用等宽数字特性。

| 用途 | 字号 |
| --- | --- |
| 正文基础 | 15px，行高 1.65 |
| 长说明、卡片说明 | 14px，行高约 1.75 |
| 表单标签、筛选、表格 | 13px |
| 日期、图例、辅助说明 | 12px |
| 页面标题 | 桌面 26px，手机 24px |
| 区块标题 | 18px |
| 主要表单输入 | 16px |
| 统计卡数值 | 28px |

首页宣传标题、总分等保留适度更大的字号。管理后台采用较密的 12–15px 表格和控件层级。公式、代码和凭证保留各自用途，不强制改成正文格式。

手机录入弹窗将最终分与原始分纵向排列，分数和满分等宽，避免数值输入被挤窄。分析页的较宽表格保持科目名称横排，由表格容器左右滚动；整页不增加横向滚动。换算参考分在窄屏纵向展示，保留完整数值。

考试详情和统计分析的四象限按手机可用宽度绘制，区域名称移到图下方。屏幕尺寸变化只重绘对应的 SVG，不请求后台，也不重建反思输入、分析筛选或详情文字。分析图从当前 SVG 保存的数据重绘，避免导出时的临时数据影响屏幕图表。

## 视觉验收

使用真实 Chromium 浏览器载入分支预览中的实际 CSS、JS 和页面组件，逐页观察布局、字体、换行、主题对比度，并检查可用宽度与整页滚动宽度。JSDOM 测试只作为功能回归，不代替视觉验收。

`design/system-ui-qa/` 提供概览、记录、详情、分析、账号、录入弹窗、登录、账号找回和管理后台切换，包含 320、390、768、1024、1280px 的 iframe 尺寸和六种主题。合成数据与请求均隔离，不读取登录凭证、不访问真实成绩。浏览器可能显示常规滚动条，因此页面实际内容宽度会比 iframe 标称宽度少一个滚动条宽度。

重新生成：先运行 `node design/build-bundles.js`，再运行 `node design/build-system-ui-visual.cjs`。原详情验收页使用 `EXAM_QA_OUTPUT=design/exam-detail-qa EXAM_QA_ASSET_PREFIX=../../ node design/build-exam-detail-visual.cjs`。

本次验证不等同于真实 iPhone 软键盘和所有操作系统字体的设备测试。
